# Примеры переносимых данных v1.1.0

Примеры являются контрактными тестовыми данными. Хосты `*.example.invalid` не ведут к настоящим прокси, паролей и пользовательских профилей здесь нет. Эти файлы не подходят для проверки реального VPN.

- [Архив 1.0.x](../../core-config-shared/src/test/resources/fixtures/policy/legacy-1.0.json): папка с двумя профилями, ветки Android/Windows, общий именованный канал и иначе. Миграция сохраняет исходный архив и создаёт стабильные ID каналов в пределах владельца.
- [Рабочая область 1.1](../../core-config-shared/src/test/resources/fixtures/policy/workspace-1.1.json): по умолчанию direct; два условия используют один канал через папку; защищённый банк при недоступности папки блокируется; отдельный домен запрещён.

Формат имеет независимые версии файла (`version`) и модели маршрутизации (`schemaVersion`). `revision` относится к сохранённой политике. Применённая revision относится к конкретному живому TUN, не экспортируется и не восстанавливается из файла как подтверждение работающего подключения.

Названия объектов можно менять. Связи задаются ID, при импорте копии переназначаются все ссылки. Циклы, исчезнувшая цель и запасной direct у защищённой ветки являются ошибками. Несовместимые условия остаются в документе, но не исполняются на другой платформе.

Профиль, папка и физический канал являются конечной целью локальной ветви. Дочерние условия такого назначения редактируются в отдельном дереве самой цели, подключённом через `routeScope`. Компилятор не позволяет просто добавить локальных детей и молча проигнорировать выбранный профиль или канал. Отключение всех дочерних условий обычной развилки возвращает её сохранённое конечное действие; потомки отключённого узла не становятся отдельными корнями.

Отдельный файл `PolicyWorkspaceStore` хранит `saved` и `draft`. Черновик может содержать незавершённую правку; он не становится активной политикой. Версия из будущего не считается повреждением и не заменяется старой резервной копией.
