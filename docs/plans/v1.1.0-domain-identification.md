# Как работает защита по домену в Expert

Защита относится к соединениям, которые **совпали с условиями ветки**. После совпадения отказ выбранного выхода не разрешает прямой запасной путь. Это одинаковый контракт Windows и Android.

## Откуда берётся имя сайта

Ядро использует имя назначения, доступное в соединении, открытые поля HTTP/TLS/QUIC и сопоставление IP с ответами DNS, которые обработал LerNET. Трафик HTTPS не расшифровывается. Найденное имя помогает выбрать правило, но не является подтверждённой личностью сайта.

Имя может отсутствовать или отличаться от искомого. Например, приложение использует собственный зашифрованный DNS, подключается сразу к IP или скрывает настоящий TLS-домен через ECH. Несколько сайтов могут разделять один IP; обратное сопоставление по DNS хранит имя для адреса и не устраняет эту неоднозначность.

Если доступные данные не совпали с доменным условием, ядро продолжает проверять следующие правила. В том числе может сработать прямой маршрут по умолчанию. Галочка защиты доменной ветки не превращает неизвестное имя в совпадение и не запрещает весь нераспознанный трафик устройства.

## Как задать более строгую область

- **Приложение:** направьте весь его трафик в защищённую ветку, без обязательного доменного условия. Если при действующей защите по приложению ядро не установило владельца, соединение блокируется. Ограничения определения приложений зависят от платформы и показаны отдельно.
- **IP или подсеть:** условие работает по фактическому адресу назначения. Общий IP может захватить другие сайты, а меняющиеся адреса нужно учитывать в правилах.
- **Весь трафик:** выберите защищённый выход для общего маршрута по умолчанию, если обычный прямой выход вообще не нужен.

Доменное условие удобно для распределения сайтов, когда имя доступно. Для требования «никакое соединение этой программы не должно уйти напрямую» используйте защиту всего приложения, а не только перечень его доменов.

## Что показывает наблюдение

История соединения показывает фактически выбранную ветку ядра. Предпросмотр с отсутствующим доменом возвращает неполные данные и не подтверждает выбранный путь. Подтверждённая работа DNS и системной защиты также не доказывает, что имя любого сайта удалось определить.

Основание в закреплённом ядре: `route/rule/rule_item_domain.go` возвращает несовпадение при отсутствии имени; `common/sniff/tls.go` читает `ClientHello.ServerName`; `dns/router.go` хранит обратное сопоставление IP → имя с TTL. Флаги защиты применяются действием совпавшего правила в `route/route.go`.
