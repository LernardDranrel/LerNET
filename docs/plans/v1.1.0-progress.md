## Реализация

В обеих версиях добавлен экспертный режим с отдельной схемой устройства. Переход на вкладку не запускает сеть. Обычный VPN и экспертный режим используют одного платформенного владельца; создание второго TUN до подтверждённого закрытия первого запрещено.

| Часть | Что реализовано |
| --- | --- |
| Постоянный вход | Нативное расширение закреплённого sing-box-lx. Ingress живёт отдельно от поколений схемы; обновление не вызывает StartOrReloadService. Подтверждение содержит действительные идентификаторы и revision. |
| Схема | Direct, Block, Profile, Folder, общий Channel, дочерние деревья, замена адреса/порта назначения, проверка ссылок и циклов. Схема и список доступны на Android и Windows. |
| Сохранение | Сохранённая версия, черновик и применённая версия различаются. Архив переносит профили, папки, схему, черновик и координаты; импорт не включает правила без отдельного действия пользователя. |
| Применение | Новые потоки получают целое новое поколение; разрешённые старые потоки сохраняют прежнее. Новый совпадающий Block завершает старый поток. Неуспешная подготовка не публикуется. |
| Папки | Предпочтительный или быстрый доступный выход, реальные HTTPS-оценки, восстановление текущего транспорта и разрешённая автосмена. Смена сети инвалидирует старые оценки. |
| Холодный старт | Одно пробуждение для одновременно пришедших запросов, конечные бюджеты и очереди, сон после простоя без открытых бизнес-соединений. Проверка связи не будит спящий выход и не продлевает активность. |
| DNS и платформы | Защищённый DNS следует политике. Неизвестный владелец не получает неявного прямого выхода. Чужие платформенные ветки сохраняются и объясняются; корпоративный интерфейс Windows на Android недоступен. |

| Смена режима | Одноразовая точка восстановления фактически работавшего обычного подключения. Более позднее намерение пользователя отменяет восстановление; ошибка закрытия удерживает владение. |

## Границы гарантий

- Правила внутри живого TUN и системная защита после его исчезновения — отдельные механизмы.
- Windows: дополнительная защита всего устройства включается явно. При сбое остаётся запрет; восстановление удаляет только фильтры и службу LerNET. Время жизни разрешения собственного интерфейса проходит отдельную ревизию перед выпуском.
- Android: системный always-on/lockdown задаётся в настройках Android и действует на пользовательский профиль целиком. Выборочная защита веток после смерти VpnService не заявляется.
- Корпоративный интерфейс должен уже существовать и быть подключён. Сохранение профиля не устанавливает SSTP или другой корпоративный VPN. Полноценный собственный SSTP остаётся отдельным адаптером по утверждённому плану.
- Неизвестный владелец системного DNS может потребовать более широкого запрета. Это объясняется в интерфейсе; приложение не угадывает источник по похожему имени.
- Защита действует после совпадения условий ветки. Имя сайта может быть скрыто собственным DoH, ECH, отсутствовать при обращении к IP или быть неоднозначным на общем адресе. Неизвестный домен не отменяет обычный Direct по умолчанию. Для строгой области нужны всё приложение, IP/подсеть либо защищённый общий маршрут. [Границы определения домена](v1.1.0-domain-identification.md).
- TUN обрабатывает сетевые соединения к внешним назначениям и поддерживаемым LAN-маршрутам. Loopback/собственные адреса устройства и контрольные/bootstrap-сокеты ядра имеют отдельную область; это не исключение для бизнес-трафика защищённой ветки. Полнота LAN/IPv6 перехвата проверяется в гостевой ОС.
- Экспорт рабочей области содержит секреты профилей и требует явного подтверждения. Диагностические журналы очищаются до записи.

## Само-ревью и исправления

1. Исправлено восстановление обычного VPN после отказа запуска Expert; Stop и новые команды не оживляют старое намерение.
2. Устранена потеря владения при неподтверждённом закрытии процесса или Android JNI/TUN. Повторный пустой Close не считается доказательством закрытия.
3. Устаревшие результаты DNS/HTTPS и обращения прежнего транспорта ограждены поколением транспорта, версии схемы и сети.
4. Добавлены реальные ограничения очередей UDP и буферов TCP; переполнение не меняет порядок уже принятых датаграмм.
5. Исправлены атомарный импорт и редактирование внешнего профиля при конкурирующем изменении сохранённых данных.
6. Сложные импортированные корпоративные профили показаны с подробностями без перезаписи полей ограниченной формой.
7. Старый простой сборщик отвергает экспертный интерфейсный транспорт вместо молчаливого выхода напрямую.
8. Для Windows Expert DNS проверяется до публикации: неявные вспомогательные системные записи заменяются нативным DNS, явно используемый неподдерживаемый путь получает понятную ошибку.
9. Перед включением Windows Expert добавлено подтверждение со снимком выбранных маршрутов и доступных источников конфликта.
10. Сохранение существующих маршрутов обычного Direct и защита от повторного использования Windows NET_LUID проверяются отдельно; их нельзя считать доказанными по имени адаптера.

## Проверки перед выпуском

Чистые тесты используют подмены процессов и часов. Они не запускают VPN ноутбука. Нативные тесты используют рабочие очереди, dialers и локальные тестовые соединения без открытия TUN. UI проверяется рендерингом вне рабочего приложения.

Сетевые критерии требуют реального гостевого TUN: Windows VM и Android-эмулятор. Точные команды, результаты, хеши сборок и оставшиеся ошибки фиксируются в документе приёмки. Успешная компиляция не заменяет эти проверки.

Установленное приложение ноутбука не запускается и не перезапускается; маршруты, адаптеры, DNS, службы и WFP ноутбука не изменяются. Итоговая папка обновляется только после проверки сборок. До готовности выпуск не помечается завершённым.
