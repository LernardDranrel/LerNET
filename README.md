# LerNET

LerNET — клиент VPN и управление сетью устройства для Android и Windows. Он помогает выбрать работающий сервер, направить трафик по правилам и восстановить соединение, когда запущенный туннель перестал передавать данные. Интерфейс приложения — на русском языке.

Версия исходников: **1.1.0**. Сетевое ядро: [sing-box-lx](https://github.com/Leadaxe/sing-box-lx) **1.14.1-lx.8** с поддержкой XHTTP и [расширением LerNET](native/README.md) для постоянного TUN. Версия ядра и версия LerNET показываются отдельно.

## Возможности

- Импорт VLESS-ссылок, JSON-конфигураций, подписок и архива LerNET.
- Папки профилей, ручное переключение и автосмена внутри папки при сбое.
- Дерево правил маршрутизации с условиями по домену, стране, IP и приложению или процессу.
- Архивы маршрутов переносятся между Android и Windows. Ветки с условиями другой платформы автоматически неактивны вместе с потомками, показаны серым и сохраняются при экспорте. Для каждой платформы можно создать свою ветку.
- В Windows редактор маршрутов хранит черновик до явного сохранения; выбор процесса ищет запущенные и установленные программы и принимает файл `.exe` вручную.
- Проверка доступности сервера и HTTP-канала через профиль до подключения.
- Просмотр пути до сервера и диагностика подключений.
- «Сеть устройства»: отдельная консоль наблюдения с интерактивной схемой, объяснениями, поиском, доказательствами и сравнением снимков.
- Полный VPN и локальный HTTP/SOCKS-прокси. На Windows полный VPN запрашивает права администратора при запуске; если запрос отклонён, приложение открывается в режиме прокси.
- Проверка рабочего пути Windows и Android во время соединения через случайные 5–10 секунд после предыдущей проверки. После двух неудач LerNET переподключается или пробует другой профиль папки.

Прокси доступен на `127.0.0.1:2080`. Он обслуживает только приложения, которым этот прокси задан. Для перехвата трафика устройства нужен режим VPN/TUN.

## Экспертный режим

Вкладка **«Эксперт»** открывает отдельную рабочую область. Просмотр и редактирование схемы не включают сеть. После явного включения один общий TUN принимает сетевой трафик устройства; исходная схема пропускает его напрямую. Обычный VPN и экспертный режим используют одного владельца туннеля.

- Направляйте разные ветки через разные профили или папки, уже подключённый корпоративный интерфейс Windows, SOCKS5 либо HTTP-прокси.
- Выбирайте дерево папки, дерево профиля или выход без дочернего дерева. Общий канал изображается одним блоком со всеми входящими связями.
- Запрещайте совпавшие соединения, заменяйте адрес/порт назначения и задавайте явное поведение при недоступности выхода: запрет или прямой путь. Защищённая ветка запрещает прямой fallback.
- Настраивайте предпочтительный профиль, выбор по реальной HTTPS-задержке, восстановление и автосмену внутри папки.
- Используйте холодный старт: выход просыпается при первом запросе и засыпает после заданного простоя без открытых соединений.
- Разделяйте черновик, сохранённую и действующую версии. Применение меняет схему без пересоздания общего TUN; новые потоки используют новую версию, разрешённые прежние завершаются со своей.
- Наблюдайте фактические соединения, версии правил, выбранные выходы и причины отказов. Предпросмотр пути явно отделён от реального трафика.

Правила сайтов зависят от распознанного имени: собственный DoH, ECH и общий IP нескольких сайтов могут скрыть или сделать его неоднозначным. Для строгого охвата выбирайте всё приложение, IP/подсеть либо защищённый общий маршрут. Подробнее: [границы определения домена](docs/plans/v1.1.0-domain-identification.md).

Защита внутри действующего TUN и блокировка после его исчезновения различаются. Windows предлагает явно включаемую системную защиту **всего устройства** с отдельным восстановлением сети. На Android always-on и lockdown включаются в настройках ОС и действуют на пользовательский профиль целиком. Корпоративный интерфейс должен уже существовать: LerNET не устанавливает SSTP-подключение по одному сохранённому профилю. [Устройство защиты Windows](docs/windows-expert-protection.md) и [результаты приёмки](docs/plans/v1.1.0-acceptance.md).

## Сеть устройства

На Windows откройте **«Сеть устройства ↗»** в левой панели или в меню значка LerNET. Окно работает независимо от подключения; его закрытие не отключает VPN. На Android вход — кнопка **«Сеть устройства»** в верхней панели диагностики.

- **Исследуйте схему**: нажмите на DNS, маршруты или адаптеры, чтобы увидеть их роль и сведения Windows/Android.
- **Проверьте путь по IP**: в Windows раздел «Маршруты» рассчитывает кандидата по прочитанной таблице. Пакеты и DNS-запросы не отправляются; доступность сервера этим не подтверждается.
- **Поймите наблюдение**: у каждого источника есть объяснение, что он показывает и когда стоит проверить настройки. Карточка предупреждения называет конкретные объекты, объясняет основание вывода, возможное влияние и следующие шаги. Технические поля раскрываются отдельно вместе с их смыслом.
- **Найдите изменения**: обновите снимок и откройте «Что изменилось». Отказ в доступе или неполная выборка не выдаются за удаление настроек.
- **Разберите сбой**: Windows может записать 45 секунд событий TCP/IP в отдельную локальную ETW-сессию до 32 МБ. Запись запускается отдельной кнопкой, сохраняется в `%APPDATA%\LerNET\network-observation` и не захватывает содержимое пакетов. Доступ к источнику и права проверяются; чужие записи не останавливаются.

Windows показывает адаптеры, адреса, метрики и MTU, активные и сохранённые маршруты, системные VPN, сетевые процессы и службы, DNS/NRPT/hosts, пользовательский и WinHTTP-прокси, драйверы и привязки, брандмауэр/WFP, IPsec, NAT, Hyper-V, Wi-Fi и существующие сетевые события. У каждого источника есть время, статус и границы видимости. Установка VPN-программы или наличие виртуального адаптера сами по себе не означают конфликт.

Android показывает сети, маршруты, DNS, Private DNS, прокси и VPN, которые ОС разрешает видеть обычному приложению. Настройки чужого VPN, все процессы и фильтры Android могут быть скрыты; экран явно поясняет эти ограничения.

Снимки находятся в памяти до явного локального экспорта JSON. Сам сбор сетевого снимка не делает внешних запросов. Проверка релизов клиента описана ниже и может быть отключена. **«Узнать мой IP»** отдельно запрашивает `api.ipify.org`: сервис увидит адрес выхода этого запроса, но перечень программ и настройки устройства ему не передаются. Страна определяется по локальной базе и относится к адресу выхода; домашний IP за VPN и имя вашего провайдера этим не определяются. В интерфейсе можно отключить движение.

## Обновления

В настройках есть «Обновления LerNET». При запуске клиент проверяет стабильный опубликованный релиз GitHub не чаще раза в сутки. Автоматическую проверку можно отключить; ручная проверка доступна всегда. GitHub видит адрес выхода запроса, но профили и отчёты не отправляются.

На Windows кнопка «Скачать и обновить» загружает установщик, сверяет размер и SHA-256 из API GitHub и предлагает системный запрос UAC. Мастер узнаёт установленный LerNET, показывает обновление, останавливает именно эту копию и сохраняет данные в `%APPDATA%\LerNET`. На последнем экране есть галочка запуска. Старые установки MSI автоматически переводятся на новый мастер. Портативную копию обновляйте распаковкой нового ZIP: установщик обновляет установленную копию, а не произвольную папку с ZIP.

На Android предложение обновления открывает страницу релиза. Скачайте APK и подтвердите обновление в Android; используется прежняя подпись приложения, поэтому профили сохраняются. Установка происходит только с вашего подтверждения.

## Установка

Последний опубликованный релиз доступен в [GitHub Releases](https://github.com/LernardDranrel/LerNET/releases/latest). Там доступны APK, установщик Windows, портативный архив и контрольные суммы. Сборки создаются локально в `artifacts/` и не входят в историю исходников Git. Портативный архив нужно распаковать целиком: `LerNET.exe`, каталог `app` и встроенная Java в `runtime` должны оставаться рядом.

На Android при первом включении полного VPN нужно подтвердить системный запрос VPN. На Windows по умолчанию выбран полный VPN, поэтому при обычном запуске появляется запрос UAC. Режим запуска можно изменить в настройках. Отказ в повышении прав оставляет доступным локальный прокси.

## Сборка из исходников

Понадобятся JDK 17 или новее, Android SDK с API 36 и Git LFS. Для сборки Windows нужны Windows и Inno Setup 6.7.3 или новее. Путь к ISCC.exe задаётся через LERNET_ISCC; подробности в packaging/windows/README.md. Большие двоичные зависимости `libbox.aar`, `sing-box.exe` и DLL хранятся через Git LFS:

```powershell
git clone git@github.com:LernardDranrel/LerNET.git
cd LerNET
git lfs pull
```

Создайте `local.properties` с `sdk.dir` или задайте `ANDROID_HOME`. Файл `local.properties` и ключи подписи исключены из Git.

```powershell
.\build-local.ps1 ':app:assembleDebug' ':desktop-app:test' '--offline' '--no-daemon'
.\build-windows.ps1 -PackageOnly
```

`build-windows.ps1 -PackageOnly` собирает портативный архив и EXE-установщик без запуска приложения. Без этого флага скрипт дополнительно запускает приложение из архива: такую проверку выполняйте в отдельной тестовой Windows. Android APK выпуска собирается скриптом `packaging/android/package-release.ps1`. При первом запуске скрипт создаёт личный ключ подписи в `.release/`; сохраните резервную копию этого каталога, иначе последующие обновления APK нельзя будет подписать тем же ключом. `.release/` исключён из Git. Без ключа можно собрать отладочную APK задачей `:app:assembleDebug`.

## Структура

| Каталог | Назначение |
| --- | --- |
| `app` | Android интерфейс и сервис VPN |
| `desktop-app` | Windows интерфейс, запуск ядра и диагностика |
| `core-config`, `core-config-shared` | Импорт и хранение профилей |
| `core-engine`, `core-engine-shared` | Управление подключением и сборка конфигурации sing-box |
| `core-routing` | Дерево и компиляция правил маршрутизации |
| `core-ui` | Общие компоненты Android |
| `packaging` | Ресурсы и сценарии выпуска |
| `native`, `tools/native` | Закреплённые исходники расширения ядра, служба WFP и воспроизводимая сборка |

На Windows пользовательские профили, правила и журнал хранятся в `%APPDATA%\LerNET`. Это личные данные; содержимое каталога не входит в репозиторий или архив приложения. На Android данные хранятся в приватном хранилище приложения. Экспорт LerNET может содержать ключи доступа — передавайте его только доверенным получателям.

## Проверка

```powershell
.\build-local.ps1 ':desktop-app:test' ':app:testDebugUnitTest' '--offline' '--no-daemon'
```

Чистые desktop-тесты используют подставные обработчики и локальные фикстуры. Тесты, запускающие встроенное сетевое ядро, требуют явного `-PlernetNativeIntegration=true` и отдельной тестовой Windows. Проверка `smoke-test-windows.ps1` тоже запускает приложение. Реальный TUN, фильтры WFP и Android VpnService проверяются в изолированной среде; unit-тесты не заменяют эту проверку. [Критерии и доказательства приёмки](docs/plans/v1.1.0-acceptance.md).

Лицензии сторонних компонентов находятся рядом с ними в `desktop-app/src/main/resources/runtime/`. Исходные версии Android `libbox` и Windows sing-box закреплены в проекте для воспроизводимости сборки.
