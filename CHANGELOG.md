# История изменений

## 1.0.13

- Windows: исправлено ложное предупреждение «маршрут не через LerNET» для собственного адаптера с описанием драйвера `sing-tun Tunnel`. Проверка читает настоящее имя интерфейса Windows по его индексу, а не описание драйвера Java.
- Windows: собственный TUN исключён из определения смены внешней сети по настоящему имени; проверка чужих интерфейсов и обхода VPN через IPv6 сохранена.
- Android и Windows: единая версия клиента 1.0.13; формат профилей и пользовательские настройки сохранены. Новая стабильная версия доступна через проверку обновлений, добавленную в 1.0.12.

## 1.0.12

- Windows: новый мастер Inno Setup с явным обновлением, переходом со старого MSI, остановкой только установленной копии LerNET и галочкой запуска после завершения. Профили и настройки сохраняются.
- Windows: сигнал штатного завершения для будущих обновлений; старые версии закрываются по точному пути с остановкой только принадлежащего им ядра.
- Android и Windows: ежедневная проверка стабильных релизов и ручная кнопка в настройках. Автопроверка отключается; не отправляет профили или диагностические отчёты.
- Windows: загрузка установщика с проверкой размера и SHA-256 из GitHub перед запросом UAC. Android: переход на страницу релиза для установки APK.


- Windows: JSON сборщиков наблюдения отделён от служебного stderr PowerShell; переполнение ответа и ошибки чтения явно обозначаются, а не маскируются ошибкой разбора.
- Windows: XML WFP читается с учётом кодировки и пространств имён; ошибки XML больше не включают целый системный дамп в отчёт.
- Windows: события сохраняют статусы отдельных журналов, тип ошибки и диагностические коды без текста событий; исправлена кодировка временного сценария Windows PowerShell 5.1.

- Проверка: 46 модульных тестов и проверки установщика на фиктивных процессах прошли. Android и Windows собираются; Inno Setup компилирует мастер. Реальная миграция MSI и запуск после установки на ноутбуке не выполнялись, работающий VPN не затрагивался.

## 1.0.11

- Android и Windows: понятные пояснения ко всем источникам сетевого наблюдения, известным техническим полям и типам предупреждений.
- Предупреждения показывают конкретные адаптеры, процессы и маршруты, основание срабатывания, возможное влияние и дальнейшие проверки.
- Windows: обычные служебные маршруты отключённых интерфейсов исключены из предупреждения; оставшиеся пути сгруппированы по адаптерам.
- Интерфейс: карточки с постепенным раскрытием деталей и анимациями, фильтры наблюдений Windows, закреплённые вкладки Android, отдельные инструкции с учётом ограничений каждой ОС.
- Проверка: 94 теста прошли; интерфейс проверен на трёх ширинах Windows и в Android Compose. Работающий клиент и VPN ноутбука не запускались и не перезапускались для проверки.

## 1.0.10

- Android и Windows: новая «Сеть устройства» с интерактивной схемой настроек, объяснениями, поиском, раскрываемыми доказательствами, сравнением снимков и режимом без анимаций.
- Windows: независимое окно, подробная инвентаризация сетевых настроек, расчёт маршрута к числовому IP и потенциальные конфликты для выбранного профиля без запуска VPN.
- Windows: существующие сетевые журналы и отдельная короткая ETW-запись TCP/IP с проверкой владения сессией, автоматической остановкой и локальным ETL.
- Android: пассивное наблюдение доступных сетей и явное отображение ограничений Android, без вызова VPN-разрешения или создания второго туннеля.
- Обе платформы: явная проверка внешнего IP, локальная страна выхода и экспорт отчёта без исходной конфигурации и ключей профиля.

- Ревью: исправлены границы Android API, чтение IPsec/происхождения правил Windows, трактовка неполных данных и отмена устаревших проверок. 99 тестов прошли; реальная интеграция CIM/ETW на отдельном устройстве ещё не проверена.

## 1.0.9

- Android и Windows: несовместимые с платформой ветки маршрутов сохраняются при переносе и отображаются серыми с пояснением; они не мешают подключению и не попадают в конфигурацию ядра.
- Windows: ошибка запуска подключения теперь видна в отдельном окне и записывается в журнал.
- Android и Windows: исправлены перенос непривязанных веток, пересечение идентификаторов папок и профилей, проверка составных условий и уникальность тегов выделенных каналов.
- Android: при переключении запускается выбранный профиль, учитывается его режим; авто-смена сохраняет настройки DNS, MTU и остальные параметры подключения.
- Общая маршрутизация: поддержаны имена процессов с пробелами и Unicode, усилена проверка IPv6, зависимостей DNS и циклических связей выходов.
- Проверка: 174 модульных теста прошли; обе платформы компилируются. Приложение и VPN на ноутбуке не запускались.
- Известное ограничение: наследование общей настройки DNS после импорта ещё отличается между Android и Windows. Подробности — в `docs/cross-platform-audit-2026-09-29.md`.

## 1.0.8

- Windows: импорт архивов `.lernet.json` из Android в списке профилей.
- Windows: проверка маршрута VPN выявляет, когда трафик уходит через другой сетевой адаптер; добавлен IPv6-адрес TUN.
- Windows: установщик создаёт ярлыки в меню «Пуск» и на рабочем столе.
- Android и Windows: сохранение логики «ИЛИ» при переносе старых правил; неподдерживаемые условия приложений или процессов теперь сопровождаются понятной ошибкой.

## 1.0.7

- Windows: отдельные каналы доступны в редакторе правил и отображаются на схеме маршрутов.
- Android: соединения с отдельными каналами стали тонкими; каналы выравниваются под правилами, смещённые связи идут под прямыми углами.
- Windows: выбранный VPN сохраняется перед запросом прав администратора.
- Android и Windows: одноимённый канал показан одним блоком с отдельными точками входа для каждой ветки. В списке общий канал отмечен значком портала; открытие канала показывает все связанные правила.

## 1.0.6

- Android: отдельные каналы на схеме маршрутов располагаются ниже дерева правил; соединение подходит к каналу сверху.

## 1.0.5

- Android и Windows: проверка рабочего туннеля через случайные 5–10 секунд после предыдущей проверки, с повтором через 2 секунды после первой неудачи.
- Windows: предварительная проверка сервера и HTTP-канала допускает до 30 секунд; причины HTTP 504 записываются в журнал.
- Android: предварительная проверка допускает медленную сеть до 30 секунд, но проверки активного соединения остаются короткими.

## 1.0.1

- Android: больше расстояние между уровнями схемы маршрутов; изгиб соединительной линии ограничен расстоянием между блоками.
- Android: при перетаскивании копия блока следует за пальцем с учётом масштаба схемы.
- Android: удаление единственного дочернего «Иначе» возвращает родителю роль конечного правила с прежним действием.
- Android: подтверждение введённого значения выделено зелёной кнопкой.
- Windows: список для правила показывает запущенные и установленные программы с иконками, ищет по названию и имени процесса; можно выбрать файл `.exe` вручную.
- Windows: изменения маршрутов сначала попадают в черновик. Его можно сохранить или отменить; при переключении набора маршрутов приложение предлагает решить, что делать с несохранёнными изменениями.
